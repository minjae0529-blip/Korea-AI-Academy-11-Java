② 검색 공식 (search / find)
public Room search(int targetNo) {
    for (Room r : list) {           // 1. 하나씩 꺼내기
        if (r.getNo() == targetNo) {// 2. 일치 비교 (문자는 .equals)
            return r;               // 3. 찾으면 그 객체 즉시 반환!
        }
    }
    return null;                    // 4. 다 찾아도 없으면 빈손
}
③ 상태 변경 공식 (대출 / 체크인)
public void checkIn(int targetNo) {
    Room r = search(targetNo);      // 1. 검색 재사용
    if (r == null) { return; }       // 2. null 방어
    if (r.isReserved()) { return; } // 3. 이미 사용중 방어

    r.setReserved(true);             // 4. Setter로 상태 변경!
    System.out.println("완료!");
}

💡 3. 가장 헷갈렸던 핵심 개념 5문 5답 (초보 탈출 포인트)
Q1. 생성자 public Hotel() { this.rooms = new ArrayList<>(); } 왜 괄호를 비우고 쓸까?
👉 호텔 건물은 오픈할 때 빈 장부(리스트)를 딱 1번만 준비하면 끝납니다. 2번째, 3번째 손님이 온다고 건물을 부수고 다시 짓는(new Hotel()) 게 아니라, 지어진 건물의 메서드(checkIn)를 부르는 것이므로 밖에서 받아올 게 없습니다.
Q2. void vs return 언제 구분해서 써야 할까?
👉 void (명령): 화면에 찍고 끝날 때. main이 돌려받을 물건이 없음. | return (조회/질문): "책 찾아와", "요금 계산해줘"처럼 main이 결과물(객체, 숫자)을 받아서 if문 등으로 후속 처리해야 할 때.
Q3. Book book = library.search("자바"); 의 진짜 의미는?
👉 new로 책을 새로 만든 게 아닙니다. 도서관 책장에 꽂혀있는 기존 책 객체를 찾아와서, 그 책을 가리키는 이름표(참조 변수)를 book으로 연결한 것입니다.
Q4. 왜 book.isBorrowed() = true; 는 에러가 나고 setBorrowed(true) 를 써야 할까?
👉 isBorrowed()는 값을 꺼내보는 조회용(읽기 전용)입니다. private 변수의 상태를 바꿀 때는 반드시 값을 넘겨주는 Setter 메서드를 호출해야 합니다.
Q5. scanner.nextInt(); 뒤에 왜 항상 scanner.nextLine(); 을 넣어야 할까?
👉 nextInt()는 숫자만 가져가고 엔터키(\n)를 버퍼에 남겨둡니다. 바로 다음 문자열 입력 시 그 남은 엔터를 읽어 입력을 건너뛰므로, 엔터 청소기로 한 줄 비워줘야 합니다.
